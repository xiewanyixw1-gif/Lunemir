# Lunemir 产品需求文档

版本：0.14

阶段：Stage 1 · 多开场白与沉浸聊天

产品标语：**A world that remembers you.**

长期模块、桌面架构、四阶段范围和完整验收标准见 [长期产品规范与分阶段开发计划](PHASED_PRODUCT_SPEC.md)。该文档是后续开发的范围基线。

## 1. 产品定义

Lunemir 是面向 AI 角色扮演用户和角色创作者的沉浸式互动应用。它兼容用户已有的角色卡、世界书和提示词预设，以本地优先的方式管理聊天、角色记忆和视觉主题，并通过一部内置悬浮小手机承载角色主动消息、剧情照片、约定与线索。

产品不是单纯的聊天界面。它同时是：

1. 角色互动空间；
2. 角色卡与世界书管理工具；
3. 可检查、可调试的上下文编译器；
4. 角色生活与关系状态的表现层。

## 2. 目标用户

### 2.1 普通玩家

希望快速导入角色、连接模型并开始剧情，不需要理解复杂提示词结构。

### 2.2 高级玩家

需要管理世界书、预设、用户人设、上下文顺序、Token 预算和长期记忆。

### 2.3 内容创作者

需要制作、测试、迭代并导出角色卡、世界设定和视觉主题。

## 3. 核心价值

- **兼容已有内容**：降低迁移成本，不把用户锁在私有格式中。
- **上下文透明**：让用户知道每轮对话使用了哪些信息。
- **记忆可控**：自动记忆必须可以查看、修改、禁用和删除。
- **角色有生活感**：角色不仅在聊天框回复，也能通过手机事件与剧情产生连续性。
- **隐私默认开启**：聊天、角色卡和 API 密钥默认不上传。

## 4. MVP 范围

### 4.1 内容导入

- 导入角色卡 PNG / JSON；
- 导入世界书 JSON；
- 导入提示词预设 JSON；
- 导入前显示字段预览、未知字段和冲突提示；
- 支持新建、覆盖、合并和保存为副本；
- 保留原始文件与来源格式，便于重新导出。

首版不承诺所有扩展字段完全兼容。解析器需要输出兼容报告，不能静默丢弃数据。

### 4.2 角色与用户人设

- 角色库、搜索、收藏和标签；
- 角色头像、名称、描述、首条消息与示例对话编辑；
- 多个用户人设；
- 每次会话绑定一个用户人设；
- 角色内容与聊天存档分离，修改角色卡时不破坏历史记录。

### 4.3 聊天

- 单角色流式对话；
- 编辑、删除、继续生成和重新生成；
- 从任意消息创建剧情分支；
- 消息级书签和备注；
- 章节与存档点；
- 文本导出和完整会话导出；
- 桌面与移动端响应式布局。

### 4.4 上下文编译器

建议的默认编译顺序：

1. 系统规则；
2. 当前预设；
3. 用户人设；
4. 角色定义；
5. 世界书命中条目；
6. 长期记忆；
7. 剧情摘要；
8. 最近对话；
9. 当前用户输入。

上下文检查器显示内容来源、插入位置、Token 估算、裁剪情况和命中理由。

### 4.5 世界书

- 关键词与正则触发；
- 常驻条目；
- 条目优先级；
- 作用域：全局、角色、会话；
- 概率触发和冷却；
- 递归命中；
- 命中调试；
- 临时禁用单个条目或整本世界书。

### 4.6 记忆

首版分为四类：

- 固定记忆：由用户手动维护；
- 剧情摘要：压缩较早对话；
- 关系记忆：称呼、承诺、态度与重要事件；
- 临时状态：地点、时间、当前任务和场景状态。

自动生成的记忆进入待确认队列。用户可配置自动接受，但默认需要确认。

### 4.7 Lunemir Phone

MVP 内置四个应用：

- Messages：角色私信和离线留言；
- Album：剧情图片和附件；
- Notes：线索、约定与任务；
- Settings：通知频率、安静时段和外观。

模型不直接写入应用状态，只能建议结构化事件。事件经过格式验证、权限检查和去重后才进入存档。

### 4.8 主题

- 主色、强调色和背景；
- 模糊、透明度和圆角；
- 字体与消息气泡；
- 头像尺寸和对话宽度；
- 悬浮手机外观；
- 动画强度；
- 低性能模式。

首版使用稳定的设计变量。自定义 CSS 在安全隔离方案完成后开放。

### 4.9 模型连接

首版优先兼容 OpenAI-compatible API：

- 自定义 API URL；
- API Key；
- Model ID；
- Context Length；
- Temperature 与 Max Tokens；
- Streaming；
- 自定义请求头。

密钥默认仅保存在内存中；用户主动选择后才加密保存在当前设备。

## 5. 信息架构

- 初次引导：连接模型、导入角色、创建用户人设；
- 对话：消息、场景、输入区、上下文检查器、悬浮手机；
- 角色：角色库、详情、编辑与导入；
- 世界书：列表、条目编辑与命中调试；
- 主题：实时预览和设计变量；
- 设置：模型、数据、隐私、性能与通知。

## 6. 数据与备份

设备本地保存角色、世界书、会话、主题、记忆和手机事件。用户可导出完整备份包：

```text
lunemir-backup.zip
├─ manifest.json
├─ characters/
├─ lorebooks/
├─ conversations/
├─ memories/
├─ phone/
├─ themes/
└─ assets/
```

备份清单包含数据版本，导入时先执行迁移预检。

## 7. 隐私与安全

- 不在前端代码中嵌入平台 API 密钥；
- 不把真实密钥、角色卡和聊天提交到 Git；
- 日志不得包含消息正文和密钥；
- 外链图片、字体和主题资源需要明确授权；
- 导入文件视为不可信内容；
- 角色卡和世界书文本不能获得脚本执行能力；
- 删除角色时分别确认角色、聊天和素材的处理方式；
- 崩溃报告默认不包含用户内容。

## 8. 非目标

MVP 暂不包含：

- 官方云同步与账号系统；
- 多角色群聊；
- 语音通话与实时语音；
- 插件市场；
- 内置模型额度；
- 角色公开交易市场；
- 自动执行外部工具。

## 9. 验收标准

用户应能在十分钟内完成：

1. 打开应用；
2. 配置一个兼容接口；
3. 导入角色卡与世界书；
4. 创建用户人设；
5. 开始流式对话；
6. 查看本轮世界书命中；
7. 打开悬浮手机查看角色消息；
8. 导出完整本地备份。

移动端核心流程可用；键盘导航清晰；关闭模糊和动画后功能不受影响。

## 10. v0.2 实现说明

当前版本已打通角色卡导入、本地存储、模型连接、流式对话、内嵌世界书命中、上下文预估和 JSON 备份恢复。为了维持纯静态部署，模型请求由浏览器直连用户配置的接口，API Key 仅存在页面内存中。

v0.2 当时尚未实现的验收项包括用户人设编辑、独立世界书与预设导入、消息编辑/重生成/分支、长期记忆写入，以及手机事件引擎。

## 11. v0.3 实现说明

当前版本新增独立 World Info 世界书和聊天预设自动识别。世界书导入后默认绑定当前角色，也可逐本启停；预设会读取启用的系统提示词与常用采样参数。用户人设进入上下文编译器，消息支持原位编辑和重新生成最后一条角色回复。

仍待实现的对话控制包括继续生成、消息版本历史与剧情分支；独立世界书编辑器目前只提供查看、绑定和命中调试。

## 12. v0.4 实现说明

重新生成最后一条角色回复时会保留旧版本，用户可以在同一条消息内前后切换；最后一条角色回复支持继续生成，并能将当前完整对话导出为 Markdown 文件。主题配色、玻璃模糊度、面板透明度和圆角强度会写入本地设置，并随 Lunemir 备份一同迁移。

剧情分支、自动摘要、长期记忆确认队列和 Phone Event 引擎仍属于后续阶段。

## 13. v0.5 实现说明

移动端主导航从底部移至顶部并隐藏冗余品牌按钮，为输入区和对话内容释放空间。悬浮手机入口与打开后的手机面板均支持鼠标和触摸拖动，并限制在当前视口范围内。

外观系统新增全屏毛玻璃与消息框毛玻璃两种布局。聊天背景可以使用当前角色卡图片、Lunemir 默认渐变或用户选择的本地图片；自定义图片限制为 8 MB，只写入当前设备的 IndexedDB 设置并随本地备份迁移。

## 14. v0.6 实现说明

每个角色可以保存多个独立会话，从任意消息创建剧情分支，并为当前进度创建章节点。会话管理集中提供新建、切换、重命名、删除、导出和章节点操作，避免这些按钮散落在沉浸式聊天场景中。

任意消息可以加入记忆候选，只有用户确认后的内容才会作为长期记忆进入模型上下文。悬浮手机移除尚未实现的相册和设置占位功能，只显示真实最近消息，以及当前会话的章节点和已确认记忆。

界面同步移除了无功能的附件按钮、场景区导出按钮、重复的人设编辑入口和重复的角色导入入口。导入按钮只在需要的页面或聊天顶栏出现。

## 15. v0.7 实现说明

聊天首屏移除重复角色横幅，角色设定集中到角色库；移动端顶部导航进一步缩短。消息支持删除并同步清理关联章节点和记忆候选，流式输出在用户停留底部时自动跟随。

## 16. v0.8 实现说明

新增统一 `StoryEvent` 契约和 IndexedDB v4 事件仓库。当前以独立 Conversation ID 作为过渡 Story ID：主剧情完成后，AI 可以用严格 JSON 提出手机消息；程序验证、去重并提交后才显示通知。用户在手机中的回复写入同一事件流，并在下一轮主剧情中作为“已确认的手机通信事件”进入上下文。

v0.8 仅完成单角色手机消息 MVP。独立系统窗口、剧情时钟、联系人数据库、主动行为调度、群聊和其他手机应用仍属于后续阶段。

## 17. v0.9 实现说明

角色页新增真实角色卡编辑器，支持新建、编辑、复制、头像管理、V2 JSON 导出和安全删除。编辑字段包含名称、昵称、创作者、版本、标签、人物描述、性格、当前场景、开场白、示例对话、角色专属提示词、历史后置指令和创作者备注。

删除角色会同时清理其会话与 Story Event，但至少保留一个角色。角色导出的头像会放入 Lunemir 扩展字段，重新导入 Lunemir 时可以恢复；其他兼容应用可忽略该扩展。

## 18. v0.10 实现说明

世界书页新增真实可视化编辑器，支持新建、编辑、复制、删除和 World Info JSON 导出。每个条目可以配置主要关键词、次要关键词、注入内容、启用状态、常驻、组合触发、大小写匹配、优先级和排列顺序；这些字段直接驱动当前上下文编译器，不是静态界面。

独立世界书继续按角色分别启用。新建或复制的世界书默认绑定当前角色；删除世界书时会从所有角色的绑定列表中清理，但不会修改角色卡内嵌世界书。正则关键词、概率、递归触发、扫描深度和 Outlet 等高级规则仍保留为后续阶段，界面不会伪装为已经执行。

## 19. v0.11 实现说明

设置页新增真实提示词预设编辑器，支持新建、编辑、复制、删除和兼容 JSON 导出。预设由独立模块组成，每个模块可以配置名称、内容、启用状态、系统提示或历史后置位置、优先级和排列顺序；上下文编译器按照“优先级优先、列表顺序其次”的规则注入启用模块。

编辑器提供确定性的重复内容、重名模块、叙事视角和回复长度冲突提示。预设仍可独立配置 Temperature、最大输出 Tokens 和上下文窗口，空白参数不会覆盖当前模型设置。当前版本一次启用一个预设；多预设组合、模块作用域和更复杂的语义冲突分析留给后续阶段。

## 20. v0.12 实现说明

顶部唯一的用户入口升级为真实人设库，支持新建、编辑、复制、头像管理和安全删除。人设可保存名称、摘要、身份、职业、外貌、性格、背景经历、人物关系、当前状态和专属设定；上下文编译器会把这些已填写字段明确注入模型，而不是只保存界面数据。

当前 Conversation ID 作为过渡 Story ID，每个剧情在本地设置中独立记录所用人设。切换角色、会话或剧情分支时会自动恢复对应人设，新建和复制人设会应用到当前剧情；单纯编辑其他人设不会意外切换当前身份。删除人设会清理所有指向它的剧情绑定，且系统始终保留至少一个人设。

## 21. v0.13 实现说明

修复移动端页面产生横向滚动的问题，所有主容器和内容页限制在视口宽度内。角色卡或自定义背景存在时，应用外壳不再使用不透明渐变遮住图片；全屏玻璃和消息框玻璃都读取同一个不透明度变量，范围扩展为 8%–95%，移动端不再用固定 78% 背景覆盖用户设置。

角色卡导入除标准 `first_mes` 外，也兼容常见的 `first_message`、`firstMessage`、`greeting` 和 `greetings` 字段；启动时会从仍保留的原始角色卡数据中修复旧版本未识别的开场白，未被用户修改过的空会话随后自动补入第一条角色消息。世界书升级为跨角色总库，列出所有角色卡内嵌世界书与独立世界书：内嵌条目可直接编辑，独立世界书显示全部角色绑定并可为当前角色单独启停。

提示词预设从模型设置中移出，成为一级页面，集中显示预设库、启用状态、模块数量、编辑、新建和导入操作。设置图标改用与其他导航一致的单色几何符号；用户人设仍保持唯一顶部入口，并实时显示当前剧情绑定的人设头像或名称首字。

## 22. v0.14 实现说明

角色卡默认开场白与 `alternate_greetings` 进入统一选择面板。尚未开始的会话可直接替换第一条角色消息；已有用户消息的故事会以所选开场白创建独立会话，从而保留原有聊天、记忆和分支。角色编辑器同步提供备选开场白管理，支持使用独立分隔行批量编辑。

模型设置和预设编辑器不再把最大输出限制硬编码为 32K，也允许填写非 1024 整数倍的真实模型上下文值。具体可用范围仍由所连接模型服务校验。

聊天首屏进一步减小顶部头像、操作按钮、移动端导航和发送框占比；重复的聊天页导入按钮被移除，消息操作折叠进按需展开的菜单。消息框毛玻璃模式不再为整块消息列表加不透明面板，而是只对消息和输入框施加玻璃效果，让角色背景图与正文成为视觉主体。

## 23. v0.15 实现说明

每个提示词预设新增独立的输出渲染配置，可启停安全 Markdown、选择小剧场卡片主题，并按顺序管理 Regex 查找替换规则。编辑器提供实时预览；常见预设中的 `regex_scripts` 会被识别为候选输出规则，不支持的原始字段仍完整保留。

聊天记录始终保存模型原文，美化只发生在显示层。用户可以在单条 AI 回复的操作菜单中切换“查看原文 / 查看美化”。HTML 会被转换为受控的文本、Markdown、小剧场或消息级隔离 UI，不使用 `dangerouslySetInnerHTML`；脚本、 iframe、对象、表单、外链资源和危险样式会被删除，无效、过长或疑似高风险的正则表达式自动跳过。当前版本不执行预设内 JavaScript，也不允许预设 CSS 控制应用全局界面。

## 24. v0.31 实现说明

输出格式改为“预设原生格式优先”。当启用的预设提示词或 Regex replacement 已经定义 HTML/CSS、状态栏或 UI 模板时，上下文编译器不会再追加相反的“禁止 HTML/CSS”指令，也不会强制改写为统一的 `:::status` 卡片；只有预设要求组件但没有提供格式时，才使用 Lunemir 原生状态组件作为回退。

预设的 `<style>`、class、受限内联样式和常用语义标签在单条消息的 Shadow DOM 中渲染。渲染器通过 DOM 节点白名单构建内容，不使用 `dangerouslySetInnerHTML`；脚本、事件属性、表单、媒体、远程 URL、CSS 导入与可能覆盖整个页面的固定定位均被删除或降级，因此预设 CSS 能表现原设计但不能污染主界面。

### v0.31.1 角色卡渲染优先级

角色卡扩展中的常见 Regex 输出规则与预设输出规则进入同一渲染器，执行顺序为“角色卡 → 当前预设”。角色编辑器允许单独关闭角色自带的状态栏与美化。只要角色卡或预设已经定义专属 UI，就不再追加 Lunemir 原生状态栏，避免一条回复出现两套状态组件。

显示层会识别模型误复述的完整 CSS 源码：存在专属 HTML 时将安全 CSS 放入消息 Shadow DOM，否则只从显示结果移除样式源码。该处理不写回聊天记录，不合并或重排正文段落，`<content>` 中的小说内容、空行与对话顺序保持不变。

当 Regex replacement 已包含完整 HTML/CSS 模板时，模型只生成动态字段，由 Regex 完成最终渲染；当格式只写在角色卡或预设提示词里、没有可复用 Regex 模板时，模型仍按原规范输出一次完整 HTML/CSS。两种情况不能互相替代，否则会出现有字段但没有状态栏外壳的问题。

旧模板的脚本加载占位框只能由当前 AI 回复中的声明式状态数据填充，包括状态标签、明确的状态键值、`data-*` 属性或安全 JSON。该兼容层不得读取长期记忆、剧情摘要或其他会话数据冒充本条回复的状态，也不得执行导入脚本；无法确认状态字段时应移除空占位框并保留正文。
